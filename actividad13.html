Red Team Report: My File Server 1

Evaluación de Seguridad Ofensiva, Explotación y Compromiso Total de Servidor Corporativo

Volver al Portafolio

ESTADO DEL OBJETIVO: CRÍTICO (ROOT COMPROMISE)

El equipo de Red Team logró el compromiso total del servidor My File Server: 1 (IP: 10.0.2.4), obteniendo acceso administrativo root y control absoluto de los datos mediante una cadena de fallos encadenados.

1. Resumen Ejecutivos y Alcance

Durante la evaluación se realizó un análisis ofensivo de tipo Caja Negra (Black Box) sobre el servidor corporativo vulnerable. El impacto directo implica la pérdida total de la Confidencialidad, Integridad y Disponibilidad de la información institucional.

Objetivos del Análisis

Evaluar la postura de seguridad del activo, identificar vectores de entrada potenciales y determinar el impacto real que un atacante podría causar en la infraestructura.

Alcance Técnico

IP Objetivo: 10.0.2.4
Exclusiones: Ataques DoS/DDoS, Ingeniería Social y explotación de la infraestructura física o routers intermedios.

Metodología Aplicada

Basada en estándares PTES e ISSAF dividida en 4 fases: Reconocimiento, Enumeración, Explotación y Post-Explotación / Escalada de Privilegios.

2. Reconocimiento y Enumeración

Mediante el uso de la herramienta netdiscover en Kali Linux se identificó la dirección IP activa en la red objetivo:

# Escaneo ARP local
sudo netdiscover

IP Descubierta: 10.0.2.4 (PCS Systemtechnik GmbH - My File Server: 1)

Posteriormente, se realizó un escaneo completo de puertos mediante nmap -p- -sV 10.0.2.4 identificando los siguientes servicios expuestos:

Samba SMB (Puerto 445/TCP)

Permitió conexión nula (Anonymous login successful). Se identificaron los recursos compartidos smbdata (exponiendo bitácoras /var/log como secure y sshd_config) y smbuser.

ProFTPD 1.3.5 (Puerto 2121/TCP)

Servicio FTP alternativo operando bajo parámetros inseguros por defecto, permitiendo acceso anónimo y permisos de escritura en la raíz web de Apache (/var/www/html).

OpenSSH 7.4 (Puerto 22/TCP)

Servicio de administración remota restringido exclusivamente a la autenticación mediante llaves criptográficas (denegando contraseñas convencionales).

3. Explotación y Acceso Inicial

Al analizar el archivo sshd_config obtenido de Samba, se confirmó que el servicio SSH exigía autenticación por llaves públicas/privadas. Aprovechando los permisos de escritura del servicio ProFTPD (Puerto 2121), se ejecutó la siguiente secuencia de intrusión:

  1. Generación de un par de llaves RSA de 2048 bits en la máquina de ataque (ssh-keygen -t rsa -b 2048).
  2. Inyección de la llave pública authorized_keys en el directorio personal del usuario smbuser vía FTP anónimo.
  3. Conexión SSH directa evadiendo la autenticación habitual de contraseñas:
ssh -i ./id_rsa smbuser@10.0.2.4

[smbuser@fileserver ~]$ whoami
smbuser (uid=1000)

4. Escalada de Privilegios (Root Compromise)

Una vez dentro del sistema, se inspeccionó la versión del núcleo del sistema operativo:

[smbuser@fileserver ~]$ uname -a
Linux fileserver 3.10.0-229.el7.x86_64 GNU/Linux

El Kernel resultó ser vulnerable al exploit crítico Dirty COW (CVE-2016-5195), una condición de carrera en el mecanismo Copy-On-Write que permite sobreescribir archivos de solo lectura mapeados en memoria.

Se descargó el exploit en /tmp, se compiló con gcc -pthread dirty.c -o dirty -lcrypt y se atacó directamente el archivo de credenciales /etc/passwd para remover la clave del superusuario:

[smbuser@fileserver tmp]$ ./dirty /etc/passwd "root::::root:/root:/bin/bash"
[smbuser@fileserver tmp]$ su root
[root@fileserver smbuser]# whoami
root (uid=0)

5. Plan de Remediación

  • Actualización del Kernel: Aplicar inmediatamente parches de seguridad mediante yum update kernel para corregir la vulnerabilidad CVE-2016-5195 (Dirty COW).
  • Endurecimiento de Servicios FTP: Desactivar el acceso anónimo en ProFTPD y desvincular la raíz del servidor FTP de la carpeta web pública (/var/www/html). Eliminar instancias redundantes.
  • Cierre de Sesiones Nulas en Samba: Configurar smb.conf para restringir accesos anónimos y proteger los logs en /var/log.

6. Tabla Resumen de Hallazgos

ID Vulnerabilidad Severidad Evidencia Impacto Recomendación
VULN-01 Sesión nula permitida en Samba (445/TCP) ALTA Acceso exitoso sin clave y exposición de bitácoras /var/log. Fuga de información operacional interna y mapeo de usuarios. Modificar smb.conf para deshabilitar inicios de sesión anónimos.
VULN-02 Configuración Insegura en ProFTPD (2121/TCP) ALTA Escritura anónima mapeada directamente a /var/www/html. Inyección de mecanismos de persistencia (Llaves SSH) y RCE. Desactivar FTP anónimo y separar directorios web de los de transferencia.
VULN-03 Vulnerabilidad de Kernel: Dirty COW (CVE-2016-5195) CRÍTICA Kernel 3.10.0 en CentOS 7 sin parches de seguridad. Elevación de privilegios local desde smbuser hasta root. Actualizar el Kernel inmediatamente ejecutando yum update.

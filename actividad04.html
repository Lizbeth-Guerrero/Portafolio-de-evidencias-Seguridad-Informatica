// ACTIVIDAD 04 · PARCIAL I

Una página demasiado convincente

Simulación de ingeniería social en laboratorio mediante Social-Engineer Toolkit (SET) y Credential Harvester para el análisis técnico de captura de información e identificación de phishing.

// VOLVER AL PORTAFOLIO

01 // Objetivo de la Práctica

Implementar y analizar, en un entorno de laboratorio controlado, una simulación de ingeniería social mediante Social-Engineer Toolkit (SET), utilizando una página web ficticia para comprender el funcionamiento de una técnica de captura de información y reconocer los elementos técnicos y visuales que permiten identificar un intento de phishing.

02 // Entorno de Laboratorio

Máquina Atacante

OS: Kali Linux 2026.x (IP: 192.168.1.50)
Herramienta: Social-Engineer Toolkit (SET) v8.0+ escuchando en puerto 80 HTTP.

Máquina Víctima / Cliente

OS: Workstation en red aislada (IP: 192.168.1.100)
Enfoque: Navegación en el portal fraudulento e ingreso de datos de prueba.

03 // Detalle de la Configuración en SET

1. Inicialización y Selección de Vectores

Invocación de SET con privilegios elevados y navegación en el menú para configurar el módulo de escucha de credenciales:

sudo setoolkit
// Menú: 1) Social-Engineering Attacks -> 2) Website Attack Vectors -> 3) Credential Harvester Attack Method

2. Escucha HTTP y Modificación de Parámetros POST

Se especifica la dirección IP de la máquina atacante para la captura de peticiones y se despliega el servidor web interno:

set:webattack> IP address for the POST back in Harvester: 192.168.1.50
[*] SET is running the Web Server on port 80...
[*] Information will be logged to /root/.set/reports/

06 // Indicadores de Phishing y Controles

1. Ausencia de HTTPS / SSL

Uso del protocolo HTTP inseguro sin candado de seguridad digital ni certificación SSL/TLS explícita.

2. Dirección IP Directa o Typosquatting

Acceso a través de una IP numérica directa (ej. http://192.168.1.50) en lugar de un dominio institucional verificado.

3. Coacción Psicológica

Mensajes orientados a infundir urgencia como "Su sesión ha expirado" para forzar una respuesta rápida sin verificación previa.

Control Recomendado: Autenticación Multi-Factor (MFA / FIDO2)

Implementación de tokens por hardware o claves FIDO2; impiden el acceso incluso si la contraseña en texto plano es interceptada.

Control Recomendado: Políticas DMARC / SPF / DKIM

Validación de firmas criptográficas en correos para impedir el spoofing de dominios corporativos.

07 // Conclusiones Técnico-Éticas

Sencillez del Vector de Ataque

Herramientas automatizadas como SET facilitan la clonación e intercepción de solicitudes HTTP POST en cuestión de minutos, demostrando que la complejidad técnica ya no es una barrera para los atacantes.

Riesgo del Tráfico Inseguro (HTTP)

La falta de cifrado en la transmisión web expone las credenciales ingresadas directamente en la carga útil del paquete de red, permitiendo su registro directo sin necesidad de ataques complejos.

Enfoque en Defensa en Profundidad

La mitigación del phishing requiere la articulación de controles de red (filtrado DNS/MFA) combinados con programas permanentes de concientización para el personal de la organización.

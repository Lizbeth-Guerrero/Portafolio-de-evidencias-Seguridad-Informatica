De la teoría a la práctica: walkthrough en acción

Este proyecto práctico demuestra la aplicación de metodologías avanzadas de pruebas de penetración (Pentesting) sobre la máquina virtual vulnerable Snakeoil de VulnHub.

Volver al Inicio

Introducción

El presente proyecto forma parte de la evaluación del curso Fundamentos de Ciberseguridad. Su propósito es documentar de manera estructurada el proceso de auditoría de seguridad realizado sobre un entorno controlado, aplicando metodologías reconocidas en la industria y reforzando competencias prácticas en pruebas de penetración.

Objetivos del Proyecto

  • Aplicar metodologías OWASP y PTES en un entorno realista.
  • Identificar vulnerabilidades críticas en servicios de red y aplicaciones web.
  • Documentar el proceso de explotación y mitigación de fallas.
  • Generar un informe técnico formal con hallazgos y recomendaciones.

Resumen Ejecutivo del Proyecto

Este caso de estudio documenta la aplicación de metodologías profesionales de seguridad informática (OWASP / PTES) para vulnerar y posteriormente mitigar las debilidades presentes en el servidor objetivo. La auditoría abarcó un proceso completo de reconocimiento de red, evasión de firmas perimetrales mediante ingeniería inversa en el manejo de sesiones de una API Flask, inyección de comandos dirigida hacia la shell de Linux (CWE-78) y la elevación final hacia los máximos privilegios administrativos.

Cronología del Pentesting e Informe de Hallazgos

Fase 1: Reconocimiento e Inteligencia de Red

Configurando el laboratorio en un entorno cerrado de Red NAT, se ejecutó un descubrimiento ARP pasivo mediante netdiscover aislando la dirección IP de la víctima. El posterior escaneo exhaustivo con Nmap sobre los 65,535 puertos identificó los vectores expuestos:

  • Puerto 22/TCP: Servicio SSH (OpenSSH) habilitado para administración remota.
  • Puerto 80/TCP: Servidor HTTP Apache corporativo actuando como sitio de bienvenida.
  • Puerto 8080/TCP: Servidor de desarrollo Werkzeug para Python Flask custodiado internamente por un proxy inverso Nginx.

Fase 2: Auditoría de API y Bypass de Controles de Sesión

Haciendo uso del proxy interceptor Burp Suite y fuzzing de endpoints con Dirbuster/Gobuster, se detectó una vulnerabilidad de credenciales por defecto (CWE-1392) al enviar parámetros con formato de formulario web clásico hacia la ruta /login con el usuario de desarrollo patrick. Esto permitió evadir las restricciones lógicas y exfiltrar un JSON Web Token (JWT) de acceso corporativo almacenado en las Cookies de sesión.

Fase 3: Inyección de Comandos Ofuscada (Foothold)

Utilizando el token capturado para autorizar peticiones en el endpoint protegido /run, se detectó una falla crítica de sanitización que pasaba argumentos no validados directamente a la shell subyacente de Linux (CWE-78).

Tras evadir una política restrictiva que exigía el formato de red host:port y esquivar una lista negra interna (Banned Commands Filter), se implementó una inyección posicional mediante fragmentación de cadenas de texto y tuberías (pipes). Esto consolidó una Shell Reversa interactiva con Netcat desde el servidor backend hacia la máquina atacante.

Fase 4: Post-Explotación y Escalada de Privilegios Locales

Una vez obtenida la consola remota con el usuario sin privilegios, el examen del archivo sudoers mediante el comando sudo -l expuso una configuración insegura de control de acceso (CWE-269). Al recuperar la frase de contraseña criptográfica remanente incrustada en el código fuente de la aplicación Flask, el sistema autenticó la solicitud, transformando el prompt ordinario en una consola interactiva de superusuario Root y permitiendo la lectura de la bandera final (proof.txt).

Matriz de Mitigación y Remediaciones Sugeridas

Para elevar el nivel de madurez en seguridad del servidor auditado, se proponen los siguientes controles técnicos:

Vulnerabilidad Hallada CWE ID Nivel de Riesgo Remediación Técnica Recomendada
Credenciales por defecto / Débiles CWE-1392 ALTO Implementar políticas de contraseñas robustas y desactivar cuentas de desarrollo predeterminadas en ambientes de producción.
Inyección de Comandos de Sistema CWE-78 CRÍTICO Reemplazar llamadas directas a la shell (`subprocess.Popen(shell=True)`) por APIs nativas parametrizadas y listas blancas de caracteres.
Escalada por Permisos Sudo Flexibles CWE-269 CRÍTICO Restringir las reglas de `sudoers` aplicando el Principio del Menor Privilegio (PoLP) y eliminar claves/passwords incrustadas en código.

Conclusiones

El proyecto permitió comprender la importancia de aplicar metodologías formales en pruebas de seguridad, así como la necesidad de implementar controles adecuados para mitigar riesgos. Se reforzaron competencias técnicas en análisis de vulnerabilidades y se desarrolló pensamiento crítico para la documentación de hallazgos.

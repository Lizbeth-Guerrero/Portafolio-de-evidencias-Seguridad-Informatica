Resumen Ejecutivo del Proyecto

Este caso de estudio documenta la aplicación de metodologías profesionales de seguridad informática (OWASP / PTES) para vulnerar y posteriormente mitigar las debilidades presentes en el servidor objetivo. La auditoría abarcó un proceso completo de reconocimiento de red, evasión de firmas perimetrales mediante ingeniería inversa en el manejo de sesiones de una API Flask, inyección de comandos dirigida hacia la shell de Linux (CWE-78) y la elevación final hacia los máximos privilegios administrativos.

Cronología del Pentesting e Informe de Hallazgos

Fase 1: Reconocimiento e Inteligencia de Red

Configurando el laboratorio en un entorno cerrado de Red NAT, se ejecutó un descubrimiento ARP pasivo mediante netdiscover aislando la dirección de la víctima. El posterior escaneo exhaustivo de Nmap sobre los 65,535 puertos reveló los vectores abiertos: puerto 22 (SSH), puerto 80 (Servidor Apache corporativo) y puerto 8080 (Servidor de desarrollo Werkzeug para Python Flask) custodiado por un proxy inverso Nginx.

Fase 2: Auditoría de API y Bypass de Controles de Sesión

Haciendo uso del proxy interceptor Burp Suite y fuzzing de endpoints, se detectó una vulnerabilidad de credenciales por defecto (CWE-1392) al enviar parámetros con formato de formulario web clásico hacia la ruta /login con el usuario de desarrollo patrick. Esto permitió evadir las restricciones lógicas y exfiltrar un JSON Web Token (JWT) de acceso corporativo almacenado en Cookies.

Fase 3: Inyección de Comandos Ofuscada (Foothold)

Utilizando el token capturado para explotar el endpoint protegido /run, se detectó una falla crítica de sanitización que pasaba argumentos directamente a la shell de Linux (CWE-78). Tras evadir una política restrictiva que exigía el formato de red host:port y una lista negra interna (Banned Command), se implementó una inyección posicional mediante fragmentación de strings y tuberías, consolidando con Netcat una Shell Reversa interactiva desde el backend hacia la estación del auditor.

Fase 4: Post-Explotación y Escalada de Privilegios Locales

Ya en la consola remota, el examen de los privilegios asignados con sudo -l expuso la vulnerabilidad de control de accesos (ALL : ALL) ALL (CWE-269). Al recuperar la frase de contraseña criptográfica remanente del código fuente de la aplicación Flask, el sistema validó el acceso local, transformando de inmediato el prompt ordinario en la consola interactiva del superusuario Root y completando la recolección de la bandera de auditoría.
